Der Theme Builder (Figma-Plugin *Lazy Theme Builder APCA*) verbindet die Paletten mit den Farbrollen der System-Collection und prüft dabei, ob Schrift und Flächen ausreichend Kontrast haben.

## Farbrollen

Die Benennung folgt dem Vorbild von Material Design 3: Zu jeder **Fläche** gibt es eine **On-Farbe** für Schrift, Icons und Konturen darauf. Statt Primary, Secondary und Tertiary gibt es **Brand** und **Action**.

| Kategorie | Rollen | Zweck |
| --- | --- | --- |
| Corporate | Brand, Action, Signal | Marke, klickbare Elemente, Hervorhebungen |
| Basic | Surface, On-Surface, Outline | Hintergründe, Schrift, Konturen |
| Feedback | Error, Warning, Success, Information | Rückmeldungen |
| Interaction | Hovered, Pressed, Focused, Disabled | Zustände |
| Effects | Shadow, Scrim | Schatten, Abdunklung |

Jede Rolle gibt es in zwei **Polaritäten** – `Default` und `Inverted` (die Gegenfläche) – und in mehreren **Emphasis-Stufen** (`Subtle`, `Base`, `Bold` …). Flächen mit der Endung *Subtle* sind so hell (bzw. im Dark Mode so dunkel), dass darauf auch die normalen Schriftfarben von On-Surface funktionieren.

## Ablauf im Plugin

1. **Paletten zuweisen** – jeder Rolle eine Palette zuordnen (z. B. Brand → Bordeaux, Surface → Clay).
2. **Tints zuweisen** – für jede Fläche und jede On-Farbe eine Stufe der Palette wählen.
3. **Dark Mode** ergänzen (optional).
4. **Weitere Rollen** ergänzen (optional) – z. B. eine dritte Markenfarbe oder Akzentfarbe. Neue Rollen brauchen immer ihr On-Gegenstück und dieselbe Polaritäts- und Emphasis-Struktur; ihr Name muss über alle Kategorien eindeutig sein.

## Prüfregeln

Der Theme Builder prüft jede Farbe gegen ihren passenden Hintergrund:

| Regel | Farbe | geprüft gegen |
| --- | --- | --- |
| 1 | `On-<Rolle>/<Polarität>/<Emphasis>` | `<Rolle>/<Polarität>/<Emphasis>` – die eigene Fläche |
| 2 | Flächen `<Rolle>/<Polarität>/<Emphasis>` | `Surface/Default/Base` – der Seitenhintergrund |
| 3 | `On-Surface/<Polarität>/*` | `Surface/<Polarität>/Base` |

**Kontrastmethoden:** Standard ist **APCA** (Accessible Perceptual Contrast Algorithm, Kandidat für WCAG 3). APCA berücksichtigt, dass helle Schrift auf dunklem Grund anders wahrgenommen wird als umgekehrt, und gibt einen Wert *Lc* zwischen etwa −108 und 106 aus. Alternativ wird nach **WCAG 2** gerechnet (Verhältnis 1:1 bis 21:1).

Für die Bewertung dient diese Einteilung nach APCA:

| \|Lc\| | geeignet für |
| --- | --- |
| ab 75 | Fließtext |
| ab 60 | Text in Komponenten, UI-Elemente |
| ab 45 | große Schrift, Überschriften |
| ab 30 | Platzhalter, Deaktiviertes, Dekoration |
| unter 30 | nicht für Inhalte |

<Aside type="caution" title="Zu entscheiden">
  Das Plugin zeigt die Werte bisher ohne Schwellen an. Die Einteilung oben ist ein Vorschlag nach den APCA-Empfehlungen und sollte als verbindliche Regel festgelegt werden.
</Aside>

## Dark Mode

Der Dark Mode entsteht als zweiter Modus der System-Collection – erst nachdem der Light Mode getestet und in Wireframes erprobt ist. Es gibt zwei Strategien:

| Strategie | Vorgehen | Vorteil | Nachteil |
| --- | --- | --- | --- |
| **Invertieren** | Alle Farben tauschen – Schwarz wird Weiß, Bold und Subtle tauschen | Kontraste bleiben ziemlich sicher erhalten | sehr helle Flächen im Dark Mode; für Text auf Bildern braucht es eine zusätzliche Rolle |
| **Dunkle Flächen** | Alle Flächen werden dunkel, alle On-Farben hell; Subtle wird zur dunkelsten Stufe, Bold heller (bis L 0,4) | keine grellen Flächen | Kontraste müssen geprüft werden, Flächen können unharmonisch wirken |

## Themes

Gibt es mehrere Marken-Erscheinungsbilder, liegt in Figma eine **Theme-Collection** vor der System-Collection. Sie ordnet die Paletten der Corporate-Rollen je Theme zu; Light und Dark stehen dabei im Variablennamen (`Light-Mode/Brand/…`, `Dark-Mode/Brand/…`), weil Figma ohne Organization-Plan nicht genug Modi erlaubt. Im Code werden Themes über `data-theme` umgeschaltet (siehe [Modi](../../reference/modes/#theme)).

## Export

Das Plugin kann die System-Collection als CSS ausgeben. Für Projekte im Repo ist der Weg über das [Austauschformat](../../reference/exchange-format/) vorgesehen – der Build erzeugt dann CSS nach der Spezifikation, inklusive Theme, Dark Mode und Farben mit Deckkraft.
