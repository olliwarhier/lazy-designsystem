Ein Modus ist eine alternative Wertetabelle für dieselben Token-Namen. Die Semantik bleibt gleich, nur die Darstellung ändert sich. Im Code gibt es vier unabhängige Achsen.

| Achse | Figma | Automatisch | Manuell |
| --- | --- | --- | --- |
| Farbschema | System: Light-Mode / Dark-Mode | `prefers-color-scheme` | `data-color-scheme="light"` oder `"dark"` |
| Kontrast | System: Kontrast-Modi | `prefers-contrast: more` | `data-contrast="more"` oder `"standard"` |
| Theme | Theme-Collection | – | `data-theme="<name>"` |
| Responsive | Responsive: Desktop / Mobile (/ Tablet) | Viewport-Breite | – |

## Farbschema und Kontrast

Ohne Attribut folgt die Seite der Systemeinstellung. Ein Attribut überschreibt sie – für einen Umschalter auf der Website oder für einzelne Bereiche (z. B. eine dunkle Sektion auf einer hellen Seite).

```html
<!-- folgt dem System -->
<html>

<!-- immer dunkel -->
<html data-color-scheme="dark">

<!-- nur diese Sektion dunkel -->
<section data-color-scheme="dark">…</section>
```

Der Build erzeugt dafür diese Struktur:

```css
:root { /* Light-Werte */ }

@media (prefers-color-scheme: dark) {
  :root:not([data-color-scheme='light']) { /* Dark-Werte */ }
}
[data-color-scheme='dark'] { /* Dark-Werte */ }
[data-color-scheme='light'] { /* Light-Werte */ }
```

Kontrast-Modi folgen demselben Muster mit `prefers-contrast` und `data-contrast`. Sie überschreiben nur die Tokens, die sich ändern – alle anderen erben vom aktiven Farbschema.

<Aside>
  Jeder Block setzt zusätzlich die CSS-Eigenschaft `color-scheme`, damit Scrollbars, Formularelemente und Systemfarben des Browsers passen.
</Aside>

## Theme

Ein Theme tauscht die Paletten der Marken-Rollen (Brand, Action, Signal). Das erste Theme in Figma ist der Standard, jedes weitere wird über ein Attribut aktiviert:

```html
<body data-theme="wireframe">
```

Ein Theme kombiniert sich automatisch mit Farbschema und Kontrast – `data-theme="wireframe"` im Dark Mode nutzt die Dark-Werte des Wireframe-Themes.

## Responsive

Responsive-Tokens springen nicht an Breakpoints, sondern **wachsen fließend** zwischen dem Mobile- und dem Desktop-Wert. Der Build erzeugt dafür `clamp()`:

```css
/* Spacing/Dynamic/Small: Mobile 12 px, Desktop 16 px */
--spacing-dynamic-small: clamp(0.75rem, calc(0.3756vw + 0.662rem), 1rem);
```

Die Formel:

- Steigung = (Desktop − Mobile) ÷ (Viewport Desktop − Viewport Mobile)
- Achsenabschnitt = Mobile − Steigung × Viewport Mobile
- Ergebnis: `clamp(Mobile, Steigung × 100vw + Achsenabschnitt, Desktop)`, alle px-Werte in `rem` (÷ 16)

Die Viewport-Breiten kommen aus `Breakpoint` der Responsive-Collection (Desktop- und Mobile-Modus). Sind beide Werte gleich, wird ein fester `rem`-Wert ausgegeben.

**Mit Tablet-Modus** wird in zwei Abschnitten interpoliert: Mobile → Tablet und Tablet → Desktop, umgeschaltet per Media Query an der Tablet-Breite.

**Einheiten:** Größen und Abstände in `rem`, Zeilenhöhen ohne Einheit (`130%` → `1.3`), Laufweite in `em`.
