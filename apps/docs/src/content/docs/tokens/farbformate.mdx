## OKLCH als Standard

Alle Farben werden als `oklch()` ausgegeben. Paletten werden im OKLCH-Farbraum erzeugt, daher bleibt die Information über Helligkeit, Sättigung und Farbton im Code lesbar und berechenbar.

```css
--palette-clay-70: oklch(0.7 0.01 127);
```

Rundung: Lightness und Chroma auf 3 Nachkommastellen, Hue auf ganze Grad.

Die Werte werden aus den Farben in Figma berechnet. Figma speichert sRGB – sehr helle oder gesättigte Stufen hat der Tint-Generator dafür bereits in den sRGB-Farbraum gebracht. Im CSS stehen deshalb genau die Farben, die auch in Figma zu sehen sind, und nicht die ursprünglichen Generator-Parameter (die stehen in den Paletten-Specs).

## Abgeleitete Farben mit Deckkraft

Outline, Interaction (Hovered, Pressed), Shadow und Scrim sind in Figma Aliase auf eine Palettenstufe **mit eigener Deckkraft**. Im CSS werden sie mit relativer Farbsyntax ausgegeben, damit der Bezug zur Palette erhalten bleibt:

```css
--color-outline-default-base: oklch(from var(--palette-clay-70) l c h / 0.64);
--color-hovered-default-base: oklch(from var(--palette-clay-10) l c h / 0.08);
```

## Interaction: Hover und Pressed

Hover und Pressed werden **aus der Farbe der Fläche berechnet**: Ihre Lightness wird um einen festen Schritt verschoben – auf hellen Flächen nach unten, auf dunklen nach oben. Farbton und Sättigung bleiben erhalten.

| Zustand | dunkler | heller |
| --- | --- | --- |
| Hovered | `--interaction-hovered-darker` (0,08) | `--interaction-hovered-lighter` (0,12) |
| Pressed | `--interaction-pressed-darker` (0,16) | `--interaction-pressed-lighter` (0,24) |

Aufhellen braucht größere Schritte, weil helle Abstufungen schwächer wahrgenommen werden. Die Schrittweiten kommen aus Figma: Dort ist Interaction ein halbtransparentes Overlay (`Color/Interaction/…`), dessen Deckkraft im Code als Lightness-Schritt verwendet wird.

```css
.button {
  background-color: var(--button-background);
}
.button:hover {
  background-color: oklch(from var(--button-background) var(--interaction-hovered-l) c h);
}
.button:active {
  background-color: oklch(from var(--button-background) var(--interaction-pressed-l) c h);
}
```

`--interaction-hovered-l` und `--interaction-pressed-l` enthalten die Rechnung für den neuen Lightness-Wert. Die Richtung ergibt sich **automatisch** aus der Fläche: Lightness über 0,5 → dunkler, darunter → heller. Das funktioniert damit auch im Dark Mode und in jedem Theme ohne weitere Angaben.

Mit `data-interaction="darker"` oder `"lighter"` lässt sich die Richtung erzwingen – das entspricht der Eigenschaft *Interaction* der Figma-Komponenten.

### Ohne Fläche

Hat eine Komponente keine Hintergrundfarbe (z. B. Outlined- und Text-Buttons), gibt es keine Lightness zum Verschieben. Dann wird die halbtransparente Interaction-Farbe als Hintergrund gesetzt:

```css
.button-text:hover {
  background-color: var(--color-hovered-default-base);
}
```

Auf dunklen Flächen wird die `inverted`-Variante verwendet.

## Hex als optionaler Export

Für Umgebungen ohne OKLCH-Unterstützung (ältere Tools, E-Mail, Diagramm-Bibliotheken) stehen die Hex-Werte jedes Tokens und jedes Modus bereits in `tokens.json` – abgeleitete Farben vorab ausgerechnet (`#rrggbbaa`). Eine eigene CSS-Datei mit Hex-Werten ist geplant.

<Aside>
  Die Hex-Werte entstehen mit demselben Gamut-Mapping wie im Browser (CSS Color 4, MINDE-Verfahren). Eine OKLCH-Farbe und ihr Hex-Gegenstück sehen daher identisch aus.
</Aside>
