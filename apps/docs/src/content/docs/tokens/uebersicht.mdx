Diese Seiten sind die **Vorgabe** des Systems: Sie legen fest, wie Tokens strukturiert, benannt und in Code übersetzt werden. Jedes Projekt bringt eigene Werte mit (Farben, Schriften, Skalen) – die Struktur ist immer dieselbe. Dadurch können Designer:innen, Entwickler:innen und LLMs sich auf dieselben Namen verlassen.

## Der Weg eines Tokens

1. **Figma Variables** sind die Quelle der Wahrheit. Die Lazy-Plugins helfen beim Aufsetzen (Paletten, Theme, Typescale).
2. **JSON** im W3C-Design-Tokens-Format ist das neutrale Austauschformat zwischen Figma, Website und Code – siehe [Austauschformat](../austauschformat/).
3. **CSS Custom Properties** werden aus dem JSON gebaut. Komponenten jedes Frameworks verwenden nur diese.

## Ebenen

Tokens bauen in festen Ebenen aufeinander auf. Eine Ebene darf nur auf die Ebenen *davor* verweisen.

| Ebene | Figma-Collection | Modi | Inhalt | Im Code |
| --- | --- | --- | --- | --- |
| 1. Primitives | `Primitives` | – | Base-Scale (8-px-Raster), Paletten, Schriftfamilien und -schnitte, Konturstärken, Radien | `--base-*`, `--palette-*`, `--font-*` |
| 2. Theme *(optional)* | `Theme` | ein Modus je Theme | Zuordnung von Paletten zu Marken-Rollen (Brand, Action, Signal) | Teil von `--color-*`, umschaltbar über `data-theme` |
| 3a. System Farbe | `System` | Light, Dark (+ Kontrast) | Farbrollen nach dem Paar-Prinzip Fläche / On-Fläche | `--color-*` |
| 3b. System Responsive | `Responsive` | Desktop, Mobile (+ Tablet) | Typescale, Abstände, Größen | `--typescale-*`, `--spacing-*`, `--sizing-*` |
| 4. Components | `Components` | Small, Medium, Large | Größen je Komponente | lokal in der Komponente, z. B. `--button-padding-x` |
| 5. Shapes | `Shapes` | Square … Pill | Rundungen – Look & Feel | ein Regler `--shape` (0–1) |

<Aside title="Warum gibt es die Theme-Collection?">
  Figma erlaubt ohne Organization-Plan nur eine begrenzte Anzahl Modi pro Collection. Deshalb liegen Themes in Figma als eigene Collection *vor* System, und Light/Dark steckt dort im Variablennamen. Im Code gibt es diese Einschränkung nicht: Theme, Farbschema und Kontrast sind dort unabhängige Achsen – siehe [Modi](../modi/).
</Aside>

## Grundregeln

- **Primitives werden nie direkt in UI oder Komponenten verwendet.** Komponenten greifen nur auf System- und Shape-Tokens zu.
- **Jeder Token hat genau einen Namen** – in Figma, im JSON und im CSS lässt er sich eindeutig ineinander übersetzen (siehe [Benennung](../benennung/)).
- **Werte werden nicht im Code geändert.** Änderungen passieren in Figma und kommen über das Austauschformat in den Code.
- **Meta-Variablen** (z. B. Paletten-Specs, Skalenfaktor, Breakpoints) steuern die Erzeugung von Werten, werden aber nicht als CSS-Variablen ausgegeben.
