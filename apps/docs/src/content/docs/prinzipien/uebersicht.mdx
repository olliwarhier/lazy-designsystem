Prinzipien beschreiben, **warum** das System so aussieht und sich so verhält. Sie gelten für Design und Code gleichermaßen und helfen bei Entscheidungen, die keine Komponente vorgibt.

## Aufbau eines Prinzips

Jedes Prinzip bekommt eine eigene Seite in diesem Ordner mit:

- **Name** – kurz und merkbar
- **Aussage** – ein Satz, der das Prinzip auf den Punkt bringt
- **Bedeutung** – was daraus konkret folgt, für Design und für Code
- **Beispiele** – je ein Do und ein Don't, idealerweise mit Live-Demo
- **Verbindung** – welche Tokens oder Komponenten das Prinzip umsetzen
